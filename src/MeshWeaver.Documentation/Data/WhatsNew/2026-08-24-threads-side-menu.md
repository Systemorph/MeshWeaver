# Threads got a real side menu — and the lists finally stay fresh

Working with threads now looks the way an agentic app should. The Threads page (`/{you}/Chat`)
opens with a centered *Start a conversation* prompt above the composer, and a **side menu** on the
left: a New-chat button, a search box to find the thread you mean, and your open threads — each
with a live status dot that tells you at a glance whether the agent is **evaluating**, whether
**messages are queued** behind a running round (with the count), or whether the thread is
**awaiting your input**. An ✕ on each row closes the thread (it stays searchable and can be
reopened — closing never deletes). The same menu renders on every conversation page, so navigating
between threads never loses the list; collapse it to a slim edge toggle when you want the full
width, exactly like the document index rail.

Two long-standing annoyances are gone with it. The composer no longer stretches into a huge empty
gray box on the Threads page — it sizes to what you type. And thread lists no longer freeze at
whatever they showed when the page loaded: creating, finishing, or reopening a thread now updates
every open list immediately. That freshness fix reaches beyond threads — on locally-run portals,
every live catalog and search that should update as content changes now actually does.
